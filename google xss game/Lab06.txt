 The key part of the code is:

🚨 What is happening here?

The url is extracted from the fragment (#...) via:

return window.location.hash.substr(1)


It checks if the URL starts with http:// or https://

If it does → it gets blocked

Otherwise, it dynamically creates a <script src="..."> tag

🧪 The Bypass Trick
✅ Hint 2: “Is the security check really foolproof?”

Nope. It only blocks URLs starting with http via:

url.match(/^https?:\/\//)


But if you can insert a script tag pointing to a valid JavaScript file that doesn’t include "http" at the start — it gets loaded.

The trick is: use a known JavaScript endpoint that doesn't start with http://.

🔥 Hint 4: “See if google.com/jsapi?callback=foo helps”

Google’s jsapi endpoint is known to allow callback-based loading, meaning:

<script src="//www.google.com/jsapi?callback=alert(1)"></script>


This will call alert(1) after the script loads.

And the trick here is:

//www.google.com/... is a valid script source

It does not start with http:// or https://

But the browser interprets it as a protocol-relative URL and loads it using HTTPS.
