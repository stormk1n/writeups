PRINCIPLE
Sometimes, websites only allow certain actions when a request uses a specific method — like POST. But if the website doesn't properly check who is making the request for all methods, an attacker might switch the method (like using GET instead of POST) and still perform that action. This can let them bypass security and do things they shouldn't be allowed to.



Lab09: Method-based access control can be circumvented
PRACTITIONER

METHOD
Log in using the admin credentials.
Browse to the admin panel, promote carlos, and send the HTTP request to Burp Repeater.
Open a private/incognito browser window, and log in with the non-admin credentials.
Attempt to re-promote carlos with the non-admin user by copying that user's session cookie into the existing Burp Repeater request, and observe that the response says "Unauthorized".
Change the method from POST to POSTX and observe that the response changes to "missing parameter".
Convert the request to use the GET method by right-clicking and selecting "Change request method".
Change the username parameter to your username and resend the request.


REASON BEHIND BIENG GIVEN THE ADMIN CREDS
>> Admin credentials → So you can observe the correct admin behavior
>> Normal user creds (wiener:peter) → So you can try to replicate that behavior as a non-admin and spot the flaws
